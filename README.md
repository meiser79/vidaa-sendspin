# VIDAA Sendspin

A browser-based Sendspin player for VIDAA TVs using [`sendspin/sendspin-js`](https://github.com/Sendspin/sendspin-js).

The client connects directly to a Sendspin server over WebSocket and provides a TV-friendly interface for synchronized playback, pairing by PIN, playback controls, volume control, metadata, artwork, connection status, and diagnostics.

## Features

- Direct Sendspin WebSocket connection
- Automatic connection on startup
- `player@v1` synchronized playback
- Metadata display for title, artist, album, and artwork
- Dynamic stream-quality badges (codec, sample rate, bit depth, channels)
- Play / pause / previous / next / shuffle / repeat controls
- Volume and mute control
- Dynamic PIN pairing
- Pairing window control
- Persistent WebSocket URL via `localStorage`
- Debug log
- 24-hour clock
- Navy-blue TV interface
- Remote-friendly focus styling
- D-pad / remote-control navigation with Arrow keys, OK/Enter and Back
- PWA manifest and favicon

## Default Sendspin endpoint

The default endpoint is:

```text
ws://homeassistant.lan:8927/sendspin
```

The URL can be changed under **Settings** and is stored in `localStorage`.

## Build locally

Requirements:

- Node.js
- npm

Install dependencies and build the static application:

```bash
npm install
npm run build
```

The deployable files are written to:

```text
dist/
```

## Run locally

For a quick local test:

```bash
npm run serve
```

Then open:

```text
http://YOUR-SERVER-IP:8080/
```

on the VIDAA TV.

## Docker

Build the container:

```bash
docker build -t vidaa-sendspin .
```

Run it:

```bash
docker run -d \
  --name vidaa-sendspin \
  -p 8080:80 \
  --restart unless-stopped \
  vidaa-sendspin
```

Then open:

```text
http://YOUR-SERVER-IP:8080/
```

## Pairing

Open **Settings** and use the pairing section.

The client supports:

- Dynamic PIN display
- Opening a temporary pairing window
- Cancelling an active pairing attempt
- Displaying the client ID

The pairing token is intentionally not shown in the UI.

## VIDAA notes

The application is bundled as a single browser-compatible IIFE and does not require native ES module support.

The JavaScript build target is ES2017. Missing native browser APIs such as WebSocket, Web Audio, or WebCrypto still depend on the VIDAA browser implementation.

Audio initialization is performed from the player startup flow because TV browsers may enforce autoplay restrictions.

## Remote control navigation

The interface is designed to work without a mouse cursor.

Supported controls:

- Arrow Up / Down / Left / Right: move focus between visible controls
- OK / Enter: activate the focused control
- Back: return to Now Playing; from Now Playing the app asks the browser to close
- Focused controls are highlighted with a blue focus ring

The navigation algorithm uses the on-screen position of controls, so it also works across the sidebar, playback controls, Settings, and About.

### Remote troubleshooting

Remote events are captured on `window` during the capture phase for VIDAA compatibility.
Each received remote key is written to the Debug log as:

```text
KEY key=ArrowDown code=40
```

VIDAA mandatory navigation key codes are 37/38/39/40, OK is 13 and Back is 8.
The implementation deliberately uses legacy `element.focus()` for compatibility with older VIDAA browser engines.
